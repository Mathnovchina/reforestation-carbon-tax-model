# Reforestation Policy under Carbon Taxation

Model and analysis code for a continuous-time, stock-flow-consistent (SFC) macro-financial model coupling a Goodwin–Keen economy to energy, emissions, climate, and a three-biome forest module. The model simulates the joint climate, forest, and macro-financial consequences of carbon taxation and reforestation policy over 2016–2100, and is solved with a fourth-order Runge–Kutta (RK4) integrator generated from the model equations and compiled through `Rcpp`.

---

## 1. Model overview

The model has four coupled modules, integrated as a single system of ordinary
differential equations:

1. **Macro-finance (stock-flow-consistent).** Capital, debt, wages,
   productivity, workforce, and prices. Output is supply-led with a fixed
   capital–output ratio; investment is profit-led; prices are set by a mark-up
   on unit cost; wages follow a short-run Phillips curve. Debt–investment
   dynamics can generate endogenous instability.
2. **Energy and emissions.** Emission intensity declines exogenously; an
   abatement share and an emission-reduction rate respond to the carbon price.
   Carbon-based energy is split between fossil fuel (taxed) and bioenergy
   (untaxed) by cost minimisation, linking the carbon price to forest harvest.
3. **Climate.** A three-reservoir carbon cycle and a two-layer energy-balance
   temperature model, with a Weitzman-type damage function feeding back to
   output and/or capital.
4. **Forests (boreal, temperate, tropical).** Biomass stocks grow logistically
   and are depleted by harvest and (tropical) deforestation. A deforestation-
   control rate curbs, halts, or reverses tropical deforestation and triggers
   the forest-policy cost that is subtracted from GDP.

Scenarios are selected through six switches (carbon-tax growth, deforestation-
control slope, forest-policy cost on/off, cost form, damages on/off, and the
damage-to-capital share) set at the top of `run_model.R`.

## 2. Repository layout

```
.
├── model.R                     Model definition: intermediate variables, ODEs,
│                               initial values, parameters, and the scenario switches
├── SourceCode.R                Engine: R -> C++ code generation, RK4 solver, calibration harness
├── RawCppCodeRK4.cpp           C++ template for the RK4 integrator
├── RawCppCodeMinDist.cpp       C++ template for the calibration objective (optional)
├── sourceCodeCalibration.R     Calibration helpers (optional; not needed to reproduce results)
├── run_model.R                 Run scenarios and reproduce the paper figures + 2100 summary
├── figures/                    Output figures (created when run_model.R is run)
├── paper_figures/              The exact code-generated figures as they appear in the paper
│                               (committed for reference; regenerated by the scripts)
│
└── sensitivity_analysis/
    ├── parameter_ledger.csv    Single source of truth for the full-system SA parameters
    ├── data/                   Input data for the literature cost-curve overlay
    ├── code/                   Cost-channel sensitivity analysis (2 parameters)
    ├── code_refined/           Refined cost-channel SA (higher sample sizes, convergence)
    └── code_fullsystem/        Full-system global SA (19 parameters: screening, Sobol,
                                viability, conditional drivers, policy sign-robustness)
```

See `sensitivity_analysis/README.md` for the sensitivity-analysis workflow.

## 3. Requirements

- **R** ≥ 4.1
- A **C++ toolchain** compatible with your R version
  (on Windows: [Rtools](https://cran.r-project.org/bin/windows/Rtools/);
  on macOS: Xcode command-line tools; on Linux: a standard `gcc`/`g++`).
- R packages: `Rcpp` (core model). The sensitivity-analysis scripts additionally
  use `data.table`, `ggplot2`, `dplyr`, `tidyr`, `purrr`, `patchwork`, `readr`,
  `scales`, `viridis`, `lhs`, `sensobol`, and `parallel`.

The scripts install any missing packages automatically on first run.

## 4. Running the model

All scripts assume the **working directory is the repository root** (the folder
containing `model.R` and `SourceCode.R`).

Reproduce the model runs and figures:

```r
source("run_model.R")
```

This compiles the model from `model.R`, runs the baseline and forest-policy
scenarios under two carbon-tax schedules, writes the figures to `figures/` as
both `.png` (preview) and `.eps` (publication), and prints a summary of key
2100 outcomes.

The `paper_figures/` folder holds the exact code-generated figures used in the
manuscript (main results and sensitivity analysis), committed for reference so
the outputs can be inspected without running the scripts. They are regenerated
into `figures/` and the `sensitivity_analysis/` output folders by the scripts.

To run a single scenario interactively:

```r
source("SourceCode.R")

scenario_g_p_car  <- 0.04    # carbon-tax growth rate
scenario_RD_slope <- 1/42    # deforestation-control slope (0 = baseline)
scenario_MC_on    <- 1       # forest-policy cost active
scenario_MC_mode  <- 0       # 0 = level cost, 1 = incremental cost
scenario_dam_on   <- 1       # climate damages active
scenario_f_K      <- 0       # damage-to-capital share (0 = output damages only)

sys <- cppMakeSys("model.R", reportVars = 3)
res <- cppRK4(sys)           # data frame of the full 2016–2100 trajectory
```

The first compilation generates `CppCodeRK4.cpp` and builds it with `Rcpp`;
this file is regenerated automatically and can be safely deleted.

## 5. Reproducing the sensitivity analysis

From the repository root:

```r
# Cost-channel sensitivity analysis (forest-policy cost parameters)
source("sensitivity_analysis/code/run_all.R")

# Full-system global sensitivity analysis (19 parameters)
source("sensitivity_analysis/code_fullsystem/01_morris_screening.R")
source("sensitivity_analysis/code_fullsystem/02_sobol_reduced.R")
source("sensitivity_analysis/code_fullsystem/03_viability_conditional.R")
source("sensitivity_analysis/code_fullsystem/04_policy_robustness.R")

# Refined cost-channel analysis (higher sample sizes, convergence diagnostics)
source("sensitivity_analysis/code_refined/run_refined.R")
```

See `sensitivity_analysis/README.md` for details, output locations, and the
recommended run order.
